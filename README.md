# 디스코드 모각공 봇

모각공 운영을 위한 디스코드 봇입니다. 음성 채널 참여를 추적하고 통계를 제공합니다.

## 주요 기능

- ✅ **24시간을 30분 단위로 나누어 음성 채널 참여 추적** (48개 슬롯)
- ✅ **각 30분 중 20분 이상 참여 시 출석 인정**
- ✅ **실시간 참여 시간 반영** (진행 중인 세션의 시간도 통계에 포함)
- ✅ **개인 통계**: 오늘/이번주/이번달/전체 기간 참여 시간 및 출석일수
- ✅ **운영자 전용**: 날짜별 참여 현황 확인 (유저 x 시간 O/X 표)
- ✅ **출석일수 기준 리더보드** (이번달/전체 기간)
- ✅ **운영자 전용 사용자 통계**: 출석일수 + 실제 참여 시간 확인
- ✅ **운영자 전용 디버그 도구**: 현재 추적 상태 및 데이터 확인

## 설치 방법

### 1. 필수 요구사항

- Node.js 18 이상
- 디스코드 봇 토큰
- 디스코드 서버 관리 권한

### 2. 패키지 설치

```bash
npm install
```

### 3. 환경 변수 설정

`.env` 파일을 프로젝트 루트 디렉토리에 생성하고 다음 내용을 입력하세요:

```
DISCORD_TOKEN=your_bot_token_here
CLIENT_ID=your_bot_client_id_here
ADMIN_ROLE_ID=
TIMEZONE=Asia/Seoul
```

**필수 항목:**
- `DISCORD_TOKEN`: 디스코드 개발자 포털에서 발급받은 봇 토큰
  - 위치: Discord Developer Portal > Application > Bot > Token
- `CLIENT_ID`: 봇의 클라이언트 ID (명령어 등록에 필요)
  - 위치: Discord Developer Portal > Application > General Information > Application ID

**선택 항목:**
- `ADMIN_ROLE_ID`: 운영자 역할 ID (선택사항)
  - 특정 역할을 운영자로 지정하려면 설정
  - 생략하거나 비워두면 서버 관리자 권한을 가진 사람도 `/참여현황` 명령어 사용 가능
  - 역할 ID 확인 방법: Discord 설정 > 고급 > 개발자 모드 활성화 > 역할 우클릭 > ID 복사
- `TIMEZONE`: 시간대 (기본값: Asia/Seoul)
  - 한국 시간을 사용하려면 그대로 두면 됩니다

### 4. 명령어 등록

```bash
node register-commands.js
```

### 5. 봇 실행

```bash
npm start
```

또는

```bash
node index.js
```

## 명령어

### 사용자 명령어

#### `/통계 [기간]`
개인 참여 통계를 확인합니다.
- **기간**: 오늘, 이번주 (월~일), 이번달, 전체
- **표시 정보**: 참여 시간, 출석일수, 출석한 날짜 목록 (최근 10개)
- **실시간 반영**: 현재 진행 중인 세션의 시간도 포함

#### `/리더보드 [기간] [인원수]`
출석일수 기준 리더보드를 확인합니다.
- **기간**: 이번달, 전체
- **인원수**: 표시할 상위 인원수 (기본: 10, 최대: 20)
- **순위**: 출석일수 기준으로 정렬 (🥇🥈🥉 표시)

### 운영자 전용 명령어

운영자 권한(서버 관리자 또는 `ADMIN_ROLE_ID`로 지정된 역할)이 필요합니다.

#### `/참여현황 [날짜]`
지정한 날짜의 참여 현황을 확인합니다.
- **날짜**: YYYY-MM-DD 형식 (예: 2024-01-15), 생략 시 오늘
- **표시 형식**: 사용자별로 30분 단위 슬롯의 O/X 표시 (4개씩 묶어서 표시)
- **통계**: 총 참여 인원, 평균 참여율
- **실시간 반영**: 오늘 날짜인 경우 현재 진행 중인 세션 시간 포함

#### `/사용자통계 [사용자] [기간] [날짜]`
지정한 사용자의 출석/참여 통계를 확인합니다.
- **사용자**: 통계를 확인할 사용자 선택 (필수)
- **기간**: 전체 기간, 이번달, 지정한 달, 지정한 날짜
- **날짜**: 기간이 "지정한 달" 또는 "지정한 날짜"인 경우 필수
  - 지정한 달: YYYY-MM 형식 (예: 2024-01)
  - 지정한 날짜: YYYY-MM-DD 형식 (예: 2024-01-15)
- **표시 정보**
  - 전체/이번달/지정 달: 총 참여 시간, 출석일수, 최근 출석 날짜(최대 20개)
  - 지정한 날짜: 당일 참여 시간(슬롯 단위 기록)과 출석 여부, 출석한 슬롯 목록
- **실시간 반영**: 오늘 날짜가 범위에 포함되면 진행 중인 음성 세션 시간도 자동 합산

#### `/디버그`
현재 추적 중인 사용자와 시간 슬롯 정보를 확인합니다.
- **활성 사용자**: 현재 음성 채널에 참여 중인 사용자 목록
- **시간 슬롯 정보**: 각 사용자의 현재 슬롯, 슬롯 시작 시간, 경과 시간
- **오늘 기록된 슬롯**: 오늘 날짜에 기록된 모든 시간 슬롯 데이터

#### `/데이터확인`
오늘 기록된 모든 시간 슬롯 데이터를 상세히 확인합니다.
- **사용자별 상세 정보**: 각 사용자의 총 참여 시간, 레코드 수
- **슬롯별 상세**: 각 슬롯의 참여 시간, 출석 인정 여부
- **실시간 반영**: 현재 진행 중인 세션 시간 포함

## 동작 방식

### 시간 추적 시스템

1. **30분 슬롯 시스템**: 봇은 24시간을 48개의 30분 슬롯으로 나눕니다.
   - 슬롯 0: 00:00-00:29
   - 슬롯 1: 00:30-00:59
   - ...
   - 슬롯 47: 23:30-23:59

2. **참여 추적**: 
   - 사용자가 음성 채널에 입장하면 세션이 시작됩니다
   - 1분마다 자동으로 시간 슬롯을 업데이트하여 참여 시간을 기록합니다
   - 슬롯이 변경되면 이전 슬롯의 참여 시간을 저장합니다
   - 각 슬롯에서 **20분 이상 참여 시 출석으로 인정**됩니다

3. **실시간 반영**: 
   - 현재 진행 중인 세션의 시간도 통계에 실시간으로 반영됩니다
   - `/통계` 명령어 사용 시 "진행 중 +X분 포함"으로 표시됩니다

4. **데이터 저장**: 
   - JSON 파일 기반으로 모든 참여 정보가 저장됩니다 (`data/` 폴더)
   - `sessions.json`: 음성 채널 세션 정보 (입장/퇴장 시간)
   - `timeSlots.json`: 시간 슬롯별 참여 기록 (날짜, 슬롯, 참여 시간, 출석 여부)

```
├── index.js                 # 메인 봇 파일 (봇 초기화 및 이벤트 처리)
├── config.js                # 설정 파일 (환경 변수 로드)
├── database.js              # 데이터베이스 관리 (JSON 파일 기반)
├── register-commands.js     # 명령어 등록 스크립트
├── commands/                # 명령어 파일들
│   ├── participation.js     # 참여 현황 명령어 (/참여현황)
│   ├── stats.js             # 통계 명령어 (/통계)
│   ├── leaderboard.js       # 리더보드 명령어 (/리더보드)
│   ├── debug.js             # 디버그 명령어 (/디버그)
│   ├── check-data.js        # 데이터 확인 명령어 (/데이터확인)
│   └── user-stats.js        # 사용자 통계 명령어 (/사용자통계)
├── utils/                   # 유틸리티 함수
│   ├── dateUtils.js         # 날짜/시간 유틸리티 (한국 시간대 처리)
│   └── tracker.js           # 음성 채널 추적 (세션 관리, 슬롯 업데이트)
├── scripts/                 # 유틸리티 스크립트
│   └── fix-timeslots.js     # 시간 슬롯 데이터 수정 스크립트
├── data/                    # 데이터 저장 폴더 (자동 생성)
│   ├── sessions.json        # 음성 채널 세션 데이터
│   └── timeSlots.json       # 시간 슬롯별 참여 기록
└── package.json             # 패키지 정보
```

## 24시간 운영하기 (클라우드 배포)

컴퓨터를 꺼도 봇이 계속 작동하려면 클라우드 서비스를 사용해야 합니다.

### Railway 배포 (권장)

Railway는 간단하고 무료 크레딧($5)을 제공합니다.

자세한 배포 방법은 [RAILWAY_DEPLOY.md](./RAILWAY_DEPLOY.md) 파일을 참고하세요.

**간단 요약:**
1. GitHub에 코드 업로드
2. [Railway.app](https://railway.app/) 가입 (GitHub 연동)
3. GitHub 저장소 연결
4. 환경 변수 설정 (`DISCORD_TOKEN`, `CLIENT_ID` 등)
5. 자동 배포 완료!

**Railway 관련 문서:**
- [RAILWAY_DEPLOY.md](./RAILWAY_DEPLOY.md) - 배포 가이드
- [RAILWAY_DATA_PERSISTENCE.md](./RAILWAY_DATA_PERSISTENCE.md) - 데이터 영속성 설정
- [RAILWAY_MANUAL_REDEPLOY.md](./RAILWAY_MANUAL_REDEPLOY.md) - 수동 재배포 가이드
- [RAILWAY_CHECK.md](./RAILWAY_CHECK.md) - 배포 확인 방법

### 다른 클라우드 서비스

자세한 무료 배포 옵션은 [FREE_DEPLOY_OPTIONS.md](./FREE_DEPLOY_OPTIONS.md) 파일을 참고하세요.

- **Replit**: [replit.com](https://replit.com/) - 웹 IDE, 무료 플랜 제공
- **AWS/Google Cloud**: 고급 사용자용
- **VPS 서버**: 더 많은 제어권 필요

## 기술 스택

- **Node.js**: 런타임 환경
- **discord.js**: Discord 봇 프레임워크 (v14.14.1)
- **dotenv**: 환경 변수 관리
- **JSON 파일 기반 데이터베이스**: 별도 DB 서버 없이 파일로 데이터 저장

## 주의사항

- **데이터 백업**: `data/` 폴더의 JSON 파일을 정기적으로 백업하는 것을 권장합니다
- **서버 재시작**: 봇이 재시작되면 진행 중인 세션은 데이터베이스에 저장되지만, 메모리의 활성 사용자 정보는 초기화됩니다
- **시간대**: 기본적으로 한국 시간대(Asia/Seoul)를 사용합니다. `TIMEZONE` 환경 변수로 변경 가능합니다

## 문제 해결

### 명령어가 보이지 않을 때
1. `node register-commands.js` 실행하여 명령어 재등록
2. Discord 앱을 재시작하거나 몇 분 대기 (명령어 전파 시간 필요)

### 데이터가 저장되지 않을 때
1. `data/` 폴더가 생성되었는지 확인
2. 파일 쓰기 권한 확인
3. `/디버그` 명령어로 현재 추적 상태 확인

### Railway 배포 시 문제
- [RAILWAY_CHECK.md](./RAILWAY_CHECK.md) 파일 참고
- 로그 확인: Railway 대시보드 > Deployments > Logs
